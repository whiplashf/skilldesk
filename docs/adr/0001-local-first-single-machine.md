# 本地优先单机工具，不做账号与托管服务

产品要做成开源工具，但全部需求——导入 GitHub skill、收藏、打标签、跟踪上游漂移与安装健康——都在**单台机器**上成立：数据源是本机宿主根与上游 git 仓库，使用者就是这台机器的所有者。因此 v1 明确为本地优先单机形态：无账号、无权限模型、无托管实例；全部状态在用户机器上，用户库可导出、可再导入；Lucy 与 AI 增强都是可选适配层，缺失时功能完整降级。

## 考虑过的选项

- **团队共享实例**：一台服务多人用，收藏/标签/跟踪成为共享数据——需要账号、权限、并发写与部署文档，成本翻倍且对陌生人无益。
- **托管 SaaS**：需要注册、计费、隐私政策，并把"读你本机的 skill"这件事变成别人的服务器问题。
- **静态只读站点**：无法承载写操作，而写操作正是这次产品化的核心诉求。

## 后果

- 写操作只需本机随机 token 防跨站请求，不需要用户体系（安全默认见 [ADR-0003](./0003-writable-architecture-and-safety.md)）。
- 团队共享 v1 不做；v2 用"可提交进 git 的集合定义 + 用户库导出文件"实现，而不是加多租户后端。
- 验收标准是"陌生机器 5 分钟跑通、无 Lucy 也能用"，不是"能部署给一个团队"。
