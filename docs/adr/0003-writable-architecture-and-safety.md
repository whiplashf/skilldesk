# 可写架构：单进程 API + SPA，用户数据与机器索引分存

现状是只读浏览器，而产品化需求（导入、收藏、标签、跟踪）全是写操作，所以架构必须一上手就区分两类数据：**用户手写态**用 JSON（可 diff、可提交进 git、可导出），**机器派生态**（skill 索引、内容指纹、上游检查记录、漂移判定）用 SQLite（可删可重建）。后端改用 FastAPI（写路由、请求校验、token、OpenAPI 自文档都省事），前端重写为 Vite + React + TypeScript；分发仍是 `uvx` 试跑 / `pipx` 常装，SQLite 走 stdlib。

安全默认随架构一起定：只绑 `127.0.0.1`、写操作要求本次运行生成的随机 token、所有读写限制在声明的宿主根与配置/状态目录内、安装与更新前必须 dry-run（文件清单 + 许可证 + 脚本清单 + 体积）且永不自执行 skill 内的脚本。

## 后果

- 必须修掉现存三处缺陷：`/assets/*` 路径穿越、`/api/asset` 无大小上限、`POST /api/build` 无认证。
- 两类数据分开后，用户库可以进 git 共享，机器索引可以直接删掉重建。
- 依赖清单从"零第三方依赖"放宽到 `fastapi/uvicorn/pydantic/httpx`，其余保持 stdlib。
