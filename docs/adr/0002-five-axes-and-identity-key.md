# 五个正交概念，用户标注绑上游身份而非目录名

skill 的"来源""落点""组织""标签""收藏"是五件不同的事。现状把它们挤进互相打架的四个维度（`family` 同时是仓库名、插件名和"无上游"），导致页面既不能可靠筛选也不能纠错。因此 Source、Host Root / Placement、Collection、Tag、Favorite 各自独立（定义见 [GLOSSARY.md](../../GLOSSARY.md)），用户标注（收藏、标签、集合、来源纠正）绑定在**身份键**上：有出处用 `src:<host>/<repo>@<path>`，无出处回退 `loc:<realpath 指纹>`。

## 考虑过的选项

- **目录名为键**（现状 `id` 即目录名）：重装或改名即丢标注。本机 54/133 无出处、24 个悬空软链，目录名不是稳定身份。
- **frontmatter `name` 为键**：重名严重（本机 `understand` 系 9 个、`lark*` 24 个、`coding*` 11 个），且上游改名会连带丢标注。
- **上游身份 + 落点指纹双键**（选中）：跨重装、跨多宿主软链保持稳定，monorepo 内按单 skill 路径区分。

## 后果

- 一个 skill 从"无出处"变成"有出处"（或反之）时需要一次性迁移记录，把标注搬到新键并合并。
- 身份键是用户库文件的主键，格式一旦发布必须向后兼容；变化只能靠版本号 + 迁移函数。
